# Project Navigator

Веб-инструмент для ведения учебных, рабочих и личных проектов: от требований
к проверяемым действиям, плану по доступному времени и сохранённому прогрессу.
Техническое имя Python-пакета и существующего сервиса — `studynavigator`.

**Развёрнутая версия:** [открыть сервис](https://navigator.136-234-80-52.sslip.io/).
**Код:** [wVks/intelligent_system](https://github.com/wVks/intelligent_system).
**Презентация:** [HTML-презентация проекта](presentation/index.html).

**Материалы защиты:** [план на 7:30](presentation/plan.md),
[текст выступления](presentation/speech.md),
[сравнение задания с ответом приложения](presentation/case-study.md).

Релиз от 14 ноября 2026 года развёрнут на VPS Ubuntu 24.04. Чат и анализ
используют DeepSeek V4.1 Flash; общая исследовательская библиотека индексирована
с реальными Text Embeddings v2. Публичный HTTPS `/health` вернул 200 в live-режиме.
Область выполненных проверок и ограничения результатов приведены в разделе 8.

## 1. Название проекта и описание задачи

**Project Navigator** помогает человеку понять, какой результат нужно получить,
какое действие выполнить следующим и хватает ли доступного времени. Проект
начинается с текстового описания или PDF. Подтверждённые требования связываются
с действиями, ожидаемыми артефактами и признаками готовности.

Практический результат — редактируемый план конкретной работы, в котором видны
причины выбора действий, зависимости, допущения по времени и непокрытые
требования. После выполнения действия пользователь фиксирует прогресс и
пересчитывает оставшуюся работу с учётом изменившейся занятости.

Пример: для исследования пользовательского пути недостаточно шага
«провести исследование». Нужны подготовка вопросов, пять интервью, фиксация
наблюдений, синтез проблем и рекомендации с доказательствами. У каждого действия
есть проверяемый результат. Приложение показывает, какие требования обеспечены
этими действиями; оно не оценивает качество готового отчёта автоматически.

Основание задачи — [исходный учебный PDF](Личный%20проект.pdf), страницы 1–3.
Он требует интеллектуальную систему с подключённой LLM, собственным MCP,
интерфейсом, хостингом, Eval, README и интерактивной HTML-защитой до 10 минут.
Учебная рубрика определяет состав инженерной сдачи; предметная область
самого приложения включает также рабочие и личные проекты.

## 2. Пользователь и сценарий использования

Пользователь — человек, выполняющий индивидуальный проект в ограниченное время:
студент, специалист или автор личного проекта.

1. Описывает проект текстом или загружает 1–3 текстовых PDF.
2. Проверяет цель, итоговый результат, требования, критерии и срок в карточке.
   AI-разбор доступен при подключённой модели; ручной путь не требует API.
3. Для каждого действия проверяет связанные требования, ожидаемый результат,
   признак готовности, зависимости и оценку времени с её основанием.
4. Проверяет рекомендацию нагрузки и обычный дневной лимит. Настройки отдельных
   дней раскрываются по необходимости; новый план получает резерв 20%,
   сохранённый резерв и полностью занятые дни остаются без изменений.
   Получает расписание, проверку покрытия и явный дефицит времени.
5. Выполняет ближайшее действие, отмечает завершение и фактическое время.
   Изменяет доступность и сохраняет пересчитанный план оставшейся работы.
6. При необходимости обсуждает материалы с ассистентом и открывает источники.

Проект открывается на вкладке «О проекте»: цель, результат, требования и материалы.
Порядок вкладок: «О проекте» → «Ассистент» → «Обзор» → «Действия и план» → «Аналитика».
Декомпозиция и добавление действий находятся в раскрывающемся блоке плана;
здесь задаются приоритет, его основание, зависимости и критерий готовности.
Обзор показывает ближайшее доступное действие с учётом приоритетов и зависимостей.
Изменение прогресса и карточки разделено, чтобы несохранённые правки не терялись.

В существующий проект можно добавлять PDF, текстовые описания и обзоры статей
с HTTP(S)-ссылками. URL не скачивается автоматически: поиск и ответы используют
сохранённый текст. Ссылка в ответе открывает окно с краткой выдержкой, полным
сохранённым фрагментом и оригиналом файла или статьи. Отдельной панели источников
в чате нет. Дополнительно ассистент может искать в общей серверной библиотеке
из пяти исследовательских статей. Её выводы служат справочным основанием,
а требования конкретного проекта поступают из его материалов и подтверждений
пользователя. PDF, XML и текст статей хранятся только на сервере; копий в
репозитории нет. Ссылка на исследование открывает точный фрагмент, PDF или
страницу издателя.

Аналитика показывает введённый факт, завершённые действия, сравнение оценок и
историю сохранений. Неизвестное время не заменяется нулём; даты снимков означают
время записи данных, а не подтверждённую дату работы. Ассистент получает текущий
план и последние 10 снимков. По явной просьбе может предложить добавление,
изменение или завершение действий. Кнопка «Применить к плану» сохраняет проверенное
предложение и обновляет расписание; до этого данные не меняются.
[Контракты и ограничения](docs/workspace-v3.md).

Ассистенту разрешены пошаговые решения по точному условию
из материала или сообщения пользователя. Ссылка подтверждает условие;
вывод и проверка решения выполняются моделью. Если доступен только номер,
ассистент запрашивает недостающее условие. Проверка источника не является
автоматическим доказательством математической корректности решения.

AI-декомпозиция ориентируется на пять крупных содержательных действий с
подшагами и оценками подготовки, выполнения и проверки. Существующие действия
без введённого прогресса можно объединить кнопкой «Собрать 5 действий»:
предварительный просмотр сохраняет общий бюджет, подшаги и связи с требованиями.
Группировка не подменяет содержательный AI-анализ. Однозначные команды изменения
длительности обрабатываются без LLM; «минимум по 3 часа» не уменьшает более
длительные оценки. Сохранение выполняется отдельным применением предложения.
Кнопка «Уточнить оценки с ИИ» запрашивает переоценку сохранённого плана:
объём и сложность работы, подготовку, выполнение, проверку и сопоставимый
фактический темп. Результат содержит диапазон времени и основание расчёта;
изменения сохраняются только после применения предложения. Общая теория по
трём отдельным темам доступна через MCP, но не является доказательством минут.
Ручной шаблон помечен как неоткалиброванный: его значения не выдаются за AI-анализ.
Короткое подтверждение «да, подстрой всё» связывается с последней оценкой
пользователя в текущем диалоге. Диапазон 3–4 часа сохраняется, а расписание
рассчитывается по верхней границе — 240 минут. При неизвестном объёме изменения
ассистент уточняет его без платного запроса.

В обзоре к действиям прикреплены раскрываемые блоки теории. Кнопка
«Подобрать теорию» дополняет материалы проекта короткими выдержками из Wikipedia
через бесплатный MediaWiki API: до пяти тем, до трёх одновременных запросов.
Вопросы об объяснении методов могут использовать этот же канал через MCP.
Найденные выдержки сохраняются с происхождением и ссылкой на оригинал;
они не становятся требованиями проекта. Упомянутый, но не загруженный учебник
не считается прочитанным. Поиск ограничен открытой энциклопедией, а не всем вебом.

Маршрут доступен как интерактивная схема зависимостей или список. Блоки содержат
действие, оценку, статус и дни выполнения; нажатие раскрывает результат,
критерий готовности и связь с требованиями. Схема строится из подтверждённых
AI- или вручную созданных действий без дополнительного запроса к модели.
Даты поступают из расчёта плана; устаревшие даты не выдаются за актуальные.
В боковой панели переключаются светлая, тёмная и системная темы. Предпочтения
темы и вида маршрута сохраняются в браузере. [Устройство функции](docs/route-and-theme.md).

Материалы, карточка, план, доступность и отметки выполнения сохраняются в SQLite.
История разговоров хранится на сервере в SQLite отдельно для каждого проекта
и браузерного пространства. Под ассистентом можно выбрать сохранённый чат,
начать новый или удалить ненужный. Перезагрузка страницы и переключение проектов
не очищают сообщения. В контекст модели попадают последние три пары сообщений
выбранного разговора; исторические предложения плана не содержат действующего
токена применения. История доступна при сохранении браузерного cookie.
Если дата отсутствует,
она остаётся неизвестной; дата начала планирования не подменяет внешний срок.
После изменения карточки старый план обозначается устаревшим. Версии записей
защищают от незаметной перезаписи изменений из другой вкладки.

## 3. Границы MVP и критерии готовности

| Область | Реализовано |
|---|---|
| Материалы | Добавление текста, PDF и ссылок на оригиналы статей; фрагменты, SQLite/FTS5, поиск и просмотр |
| Карточка | AI-разбор, ручное заполнение без модели, подтверждение, происхождение сведений |
| Действия | Стабильные связи с требованиями, результат, признак готовности, основание оценки, приоритет с пояснением и зависимости |
| План | Разная доступность по дням, резерв, зависимости, конкретные подшаги с минутами, покрытие и дефицит |
| Прогресс | Сохранённые завершённость и факт, история снимков, графики, пересчёт оставшейся работы |
| Ассистент | Ответы по материалам, прогрессу и общей исследовательской библиотеке; предложения add/update/complete с отдельным применением |
| Интерфейс | Отдельные экраны, диаграмма зависимостей, ближайшее действие, вместимость; светлая, тёмная и системная темы |
| Текст | Безопасные абзацы и списки в источниках/сообщениях, открытие страницы PDF |
| Хранение | Постоянные файлы и БД, изоляция анонимных браузерных сессий |
| Размещение | Один VPS, Docker Compose, Caddy HTTPS, автоперезапуск и резервное копирование |

Ограничения загрузки: **1–3 PDF, до 10 MiB суммарно, до 100 страниц и
100 000 извлечённых символов суммарно с текстовыми материалами проекта**.
Нужен текстовый слой: OCR и сканы не поддерживаются.
Повреждённые, защищённые и неподходящие файлы получают явную ошибку.

Подключённый DeepSeek V4.1 Flash получает все материалы при AI-разборе одним
запросом: до 100 000 символов исходного текста и 160 000 символов JSON с метаданными.
Для остальных провайдеров сохранена консервативная граница контекста: материалы
свыше 24 000 JSON-символов обрабатываются частями с проверкой дословных выдержек.
При превышении ёмкости анализа возвращается ошибка, а не частичный результат.
Все запросы учитываются в общем денежном бюджете и тайм-ауте анализа.

В MVP нет аккаунтов/ролей, восстановления анонимной сессии, интеграции с LMS,
уведомлений, календарей, DOCX, векторной БД, обучения модели и микросервисов.
Cookie разделяет доступ к материалам; это не полноценная система авторизации.
При утрате cookie прежнее приватное задание из другого браузера не откроется.

Критерии готовности MVP:

1. Интерфейс доступен по публичному HTTPS-адресу.
2. Анализ и чат используют подключённую LLM; доступ к материалам осуществляется
   через собственные MCP-клиент и MCP-сервер.
3. Ответ содержит ссылки на доступные источники; отсутствующий срок сохраняется
   как неизвестный.
4. Каждое обязательное требование связано с действием; у действия есть результат
   и признак готовности. Пропуски и неполная декомпозиция показаны явно.
5. Расписание сохраняет зависимости и не превышает доступные минуты по дням;
   невместившаяся работа остаётся видимой.
6. Материалы, карточки, планы, прогресс и журнал расходов сохраняются после рестарта.

Проверки перечисленных свойств выполнены на ограниченном наборе сценариев.
Результаты не подтверждают непрерывную доступность или качество на произвольных
документах.

## 4. Архитектурная схема системы

~~~mermaid
flowchart TD
  U[Браузер: описание/PDF, действия, план, прогресс, чат] --> API[FastAPI backend]
  API --> F[DeepSeek V4.1 Flash: разбор PDF]
  API --> C[Собственный MCP-клиент]
  C -->|stdio| S[Собственный MCP-сервер]
  S --> D[SQLite / FTS5 / текст и PDF]
  API --> P[DeepSeek V4.1 Flash: ответ]
  S --> K[Исследования: SQLite FTS5 и vectors]
  K --> E[Text Embeddings v2 doc/query: 768]
  API --> T[Python: зависимости, доступность, покрытие, дефицит]
  T --> W[SQLite: план и прогресс с версией]
  API --> B[Общий сохраняемый журнал расходов API]
~~~

Стек: Python 3.12, FastAPI, Pydantic, SQLite/FTS5, pypdf и HTML/CSS/JavaScript.
Зависимости закреплены в `uv.lock` и `requirements.lock`.
Извлечённые материалы индексируются при загрузке. Файлы, карточки и денежный
журнал и индекс исследований находятся в постоянном `/app/var`; общая библиотека
подключена в `/app/knowledge` только для чтения. Ключ модели — в серверном env-файле
вне исходников. Frontend не получает API-ключ.

## 5. Схема MCP-интеграции

Клиент — `studynavigator/mcp_gateway.py`, сервер —
`studynavigator/mcp_server.py`. Обмен выполняется по протоколу MCP через
транспорт stdio.

| Инструмент | Назначение |
|---|---|
| `list_assignments` | Список доступных заданий |
| `get_assignment` | Карточка, факты, требования и источники выбранного задания |
| `search_materials` | Поиск фрагментов проекта; `include_research` добавляет исследования для советов, `include_theory` — общую теорию Wikipedia |

Инструменты выполняют только чтение. Область доступа задаёт приложение;
модель не определяет владельца материалов. Код проверяет аргументы, имена
инструментов, ошибки, тайм-ауты и предел числа вызовов.

Для загруженного задания с Yandex/DeepSeek-моделью и пустым реестром типизированных фактов
приложение выполняет `get_assignment` и `search_materials`, затем передаёт данные
модели. В трассе это отмечено `initiator=application`. Для подготовленного
примера работает ограниченный цикл выбора инструментов моделью.
Оба пути используют собственный MCP, но инициатор вызовов различается.

## 6. Описание AI-логики

Текущая серверная конфигурация:

| Роль | Модель | Предел ответа |
|---|---|---|
| Разбор материалов в карточку | DeepSeek V4.1 Flash/latest | 10000 токенов |
| Ответ ассистента | DeepSeek V4.1 Flash/latest | 4000 токенов |
| Векторизация исследований и запроса | Text Embeddings v2 doc/query | 768 измерений |

Необязательный `LLM_ANALYSIS_MODEL` переопределяет только анализ.
Если он пуст, обе роли используют `LLM_MODEL`; автоматического переключения нет.
Для Yandex DeepSeek задан `reasoning_effort=none`: рассуждение не расходует лимит
структурированного ответа. Схемы карточки и ответа проверяются кодом.

Материалы проекта проходят поиск FTS5 → MCP → модель. Для общей библиотеки
в чате применяется hybrid retrieval: FTS5 и cosine similarity по embeddings
объединяются по рангам. Индекс содержит пять статей и 157 фрагментов; векторы
хранятся в SQLite, отдельного сервиса векторной БД нет. Источник цитаты — точный
фрагмент статьи с собственным ID. Исследования не включаются в AI-разбор карточки
и не становятся требованиями проекта. При недоступности embeddings поиск
возвращается к FTS5 с явным признаком ухудшенного режима. Индексация выполняется
отдельной командой с предварительной оценкой, ограничениями и кешированием;
при старте приложения платных фоновых запросов нет.
Для загруженных материалов модель получает компактный JSON-контекст и возвращает
структурированный ответ без параметра `tools`. При ошибке формата допускается
одна корректирующая генерация до 250 токенов в пределах общего тайм-аута и
денежного бюджета. Для подготовленного примера действует цикл выбора и вызова
инструментов моделью с пределом 6 вызовов.

Карточка действий включает `requirement_ids`, `expected_result`, `done_when`,
`estimate_basis`, необязательный диапазон `min_minutes`/`max_minutes` и
`depends_on`. Модель должна объяснять оценку через объём работы и допущения.
Пользователь проверяет и исправляет предложенную декомпозицию.

Действие может содержать конкретные подшаги с собственными минутами и признаком
готовности. Их время в сумме равно оценке действия. В дневном плане показывается
только выделенная на этот день часть работы; переходящий подшаг сохраняет
идентификатор и критерий готовности. Это длительности в минутах, а не назначенные
часы начала и окончания. Число пунктов определяется содержанием и доступностью:
полностью занятые дни и дни без оставшейся работы не заполняются искусственными
пятью шагами. Старые действия без подшагов сохраняются без выдуманной детализации.
Завершение и фактическое время пока фиксируются на уровне родительского действия.

Код проверяет схемы, доступность источников, типизированные факты и известные даты.
Неизвестный срок остаётся `null`; минуты являются оценкой или вводом
пользователя, а не требованием преподавателя. Суммы времени и расписание считает
Python, а не LLM. Документы и ответы инструментов — данные, не инструкции агенту.
Зависимости проходят проверку на циклы. Дневной бюджет уменьшается на выбранный
резерв; работа после известного срока исключается, если задана дата начала.
Без даты начала план остаётся относительным и не доказывает соблюдение срока.
Фактические минуты не вычитаются автоматически: остаток работы пользователь
оценивает отдельно, иначе медленная работа ошибочно выглядела бы выполненной.

Связи и заполненные поля проверяются структурно. Они не доказывают смысловую
полноту плана. У шаблонной декомпозиции явно показаны неполные результаты и
необоснованные оценки. Научные основания, границы выводов и выбранные практики
описаны в [исследовании продукта](docs/product-research.md).

Ошибки live-режима возвращаются явно, без подмены демонстрационным ответом.
Без ключа доступен обозначенный offline-режим. Валидация идентификаторов
источников не гарантирует смысловую точность свободного текста модели;
значимые утверждения требуют сопоставления с исходным документом.

## 7. Инструкция по запуску и развёртыванию

### Локальный запуск

Нужны Python 3.12 и `uv`. Из корня проекта:

~~~sh
uv sync --locked --extra dev
.venv/bin/python -m studynavigator
~~~

Открыть [localhost:8000](http://127.0.0.1:8000/).
В этом режиме используются MCP и детерминированные ответы без платных API-вызовов.
База и каталог загрузок создаются в `var/`; для остановки нажмите Control+C
в терминале запуска.

Для live создайте собственный `.env` по `.env.example`, заполните
`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`,
при необходимости `LLM_ANALYSIS_MODEL`, и выберите `STUDYNAV_MODE=live`.
URI Яндекса должен содержать каталог, доступный ключу. Запуск:

~~~sh
uv run --locked --extra dev --env-file .env python -m studynavigator
~~~

Обычный `python -m studynavigator` сам файл `.env` не читает.
Файл окружения создаётся отдельно для каждого окружения; ключи исключены из Git.
Для серверной исследовательской библиотеки задаются `STUDYNAV_KNOWLEDGE_ROOT`,
`STUDYNAV_KNOWLEDGE_DB_PATH`, `EMBEDDING_BASE_URL`, `EMBEDDING_DOC_MODEL`,
`EMBEDDING_QUERY_MODEL`, `EMBEDDING_DIMENSIONS=768`. Она использует серверный
`LLM_API_KEY` и общий `STUDYNAV_LIVE_BUDGET_PATH` / `STUDYNAV_LIVE_BUDGET_RUB`.
Индекс готовится отдельно через `tools/index_knowledge.py --root ... --db ...`;
без `--apply` команда показывает предварительную оценку, платная векторизация
требует также `--embed`. Статьи следует готовить на сервере, не скачивая их
в локальный репозиторий.

Изменение настроек требует перезапуска. Значения по умолчанию: 1000/3000 токенов
для чата/анализа, тайм-ауты провайдера/запроса 20/45 с. На VPS установлены
4000/10000 токенов для чата/анализа. Общий сохраняемый журнал расходов
ограничивает платные вызовы генерации и embeddings.

### Размещение и сохранность

Сервис размещён на VPS Ubuntu 24.04, Docker/Compose и Caddy.
Рабочая директория — `/opt/studynavigator/app`, серверный env —
`/opt/studynavigator/server.env`, права 0600, вне сборки и репозитория.

~~~sh
cd /opt/studynavigator/app
docker compose -f compose.yaml -f compose.knowledge.yaml --env-file ../server.env config --quiet
docker compose -f compose.yaml -f compose.knowledge.yaml --env-file ../server.env build app
docker compose -f compose.yaml -f compose.knowledge.yaml --env-file ../server.env up -d --wait
curl --fail https://navigator.136-234-80-52.sslip.io/health
~~~

Backend работает от UID 10001 с одним worker, корневой файловой системой только
для чтения и постоянным томом `studynavigator_app_data`. Порт 8000 наружу
не опубликован; HTTPS завершает Caddy. Настроены healthcheck, ротация логов
и `unless-stopped`.
Не используйте `down -v` для обновления; `docker compose config` запускайте
с `--quiet`, чтобы не вывести секреты. Домен технический и зависит от IP VPS.

Историческая проверка прежнего VPS: восстановление резервной копии
в отдельном offline-томе без сети подтвердило сохранность данных:
сохранены четыре задания, исходные PDF и журнал расходов. После перезагрузки VPS
HTTPS восстановился за 21,2 с. Эти проверки относятся к версии до последних
изменений интерфейса; после обновления отдельно подтверждена сохранность шести
заданий. При восстановлении старой копии требуется сохранить актуальный журнал
расходов, чтобы исключить повторное использование израсходованного бюджета.
На новом сервере проверено восстановление архива в отдельный временный каталог:
обе SQLite-базы прошли `quick_check`, сохранены пять статей, 157 векторов и точные
байты ledger. План и прогресс доступны после перезапуска контейнера. Ежедневный
таймер запускает копирование в 03:15–03:20 МСК; намеренно остановленный сервис
резервирование не включает. Инструкция: [deploy/README.md](deploy/README.md).

Исходники и зависимости приложения размещены на VPS и включены в Docker-образ.
Обращение к GitHub при запуске не требуется. Работа сервиса зависит от
доступности VPS, постоянных данных, DNS и внешнего API модели.
