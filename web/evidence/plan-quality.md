# Проверка плана по заданию «Личный проект.pdf»

Проверены два результата разбора одного трёхстраничного PDF. Для 16 ноября сохранён точный текст ответа DeepSeek V4.1 Flash и его разобранный JSON. Для 17 ноября сохранены карточка приложения и рассчитанный по ней план. Сведения о модели и исходном HTTP-ответе для второго снимка отсутствуют. [Ответы целиком](plan-model-outputs.json)

## С чем сравнивали

По заданию студент должен разместить интеллектуальную систему с интерфейсом, подключённой LLM и собственной MCP-интеграцией, опубликовать README из девяти разделов и HTML-презентацию, провести Eval, разобрать ошибки и передать в LMS две ссылки. Презентация рассчитана максимум на 10 минут. Календарной даты сдачи в документе нет. Для сравнения использованы пять фрагментов исходника, рубрика преподавателя и ручной перечень из 22 аспектов. [Фрагменты PDF и эталон](plan-source-reference.json)

## Ответ 16 ноября

Модель предложила **5 действий и 20 подшагов**. Сумма центральных оценок составляет **1020 минут (17 часов)**. Для семи критериев сопоставили конкретные поля ответа с источником и проверили расчёты. [Результаты по критериям](plan-quality-checks.json)

| Критерий | Что обнаружили |
|---|---|
| Полнота требований | Девять требований охватывают систему, хостинг, README, Eval, презентацию и LMS. В `t5s4` перечислены обе ссылки для сдачи. Публикация репозитория с обоими файлами осталась без отдельной проверки. |
| Подтверждение источником | В `req-3` модель верно требует подключить LLM, но ссылается только на S2. Там говорится об описании AI-логики в README. Подключение модели прямо указано в S1. |
| Точность рубрики | В обосновании приоритета `t2` MCP и AI названы двумя отдельными критериями оценки. В рубрике выделена категория MCP на 10 баллов. AI-логика входит в требования к системе. |
| Неизвестные сведения | Срок оставлен `null`; модель просит его уточнить. Количество слайдов и тестовых запросов помечено как допущение. |
| Проверяемость действий | У `t3s2` есть наблюдаемый результат: запрос проходит через интерфейс и AI. Для MCP не выделен ошибочный вызов, а для инструкции запуска — проверка в чистом окружении. |
| Обоснованность времени | В каждом из пяти действий сумма минут подшагов совпадает с центральной оценкой. Однако все пять нижних границ расходятся с собственным обоснованием модели. Например, для `t2` компоненты дают минимум 40 + 120 + 60 + 40 = 260 минут, а модель указывает 200. |
| Зависимости и границы | В графе нет циклов. Интерфейс и размещение следуют за реализацией. Подготовка презентации поставлена после полного оформления README, хотя черновик можно начать раньше. |

## Карточка и расписание 17 ноября

В карточке **7 требований, 5 критериев, 5 действий и 17 подшагов**. В `A4-s1` студенту прямо поручено создать публичный репозиторий. При этом в `req-2` перечислены восемь разделов README из девяти: пропущена архитектурная схема системы.

Планировщик получил доступность **14 дней по 150 минут**. После резерва 20% остаётся **1680 минут**. Центральные оценки действий дают **150 + 420 + 360 + 330 + 210 = 1470 минут**. При такой оценке в расписании остаётся **210 минут**. Верхняя граница оценок модели составляет **2400 минут** и превышает доступное время на **720 минут**.

Студент может принимать решения по конкретным результатам: добавить недостающий раздел README, проверить обе ссылки перед отправкой и пересчитать расписание после первого замера времени. Фактическая длительность выполнения этого задания в сохранённых данных неизвестна.
