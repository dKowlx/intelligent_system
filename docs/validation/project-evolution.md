# Локальная проверка Project Navigator

Этот отчёт фиксирует продуктовую итерацию до полного редизайна. Текущий
браузерный сценарий и результаты нового интерфейса описаны отдельно:
[проверка рабочего пространства](workspace-redesign.md).

Дата: 9 ноября 2026. Режим приложения: **offline**. Платных запросов LLM — **0**.
SSH, серверное развёртывание, commit и push не выполнялись. Рабочие `.env`,
данные опубликованного сервиса и денежные лимиты не изменялись.

## Продуктовое изменение

Приложение поддерживает учебные, рабочие и личные проекты. Описание можно
ввести текстом или загрузить PDF. Действие связывается со стабильными ID
требований и содержит результат, признак готовности, основание/диапазон оценки
и зависимости. План учитывает доступность каждого дня, резерв, завершённость
и отдельно введённое фактическое время. План и прогресс сохраняются.

Исследование: [источники и принятые решения](../product-research.md).
Основной сценарий не требует модели: ручная карточка и явно обозначенный
авторский рабочий пример доступны offline. Новый prompt подготовлен, но
его качество на реальном API в этой итерации не измерялось.

## Содержательный пример

[Эталон](../../evals/app/project-reference.json) описывает исследование поиска
функции: участники уже найдены, требуются пять интервью, синтез, три рекомендации
и отчёт с доказательствами. В файле отдельно записаны принимаемые и отклоняемые
результаты. Это инженерный эталон и пример для интерфейса, не генерация LLM.

| Требование | Недостаток прежнего шаблона | Проверяемое действие в примере |
|---|---|---|
| Пять интервью по 30 минут | «Выполнить требование», 60 минут: меньше даже длительности самих интервью | Сценарий/согласия — 45; пять интервью с заметками — 200; пять обезличенных протоколов |
| Синтез наблюдений | Нет результата и способа проверки | Таблица тем со ссылками на протоколы и противоречащие наблюдения; 90 минут |
| Три обоснованные рекомендации | Не объяснено, откуда следуют рекомендации | Каждая содержит проблему, изменение, доказательства и способ проверки; 60 минут |
| Отчёт | Общее «проверить результат» | Метод, ограничения, выводы, рекомендации, приложение; проверка ссылок и удаления персональных данных; 75 минут |

Итого: **470 минут — допущение автора примера**, а не измеренная длительность
для любого пользователя. Время распределено как **90 / 0 / 120 / 120 / 120**:
доступно 450, дефицит 20. Второй день пуст; последние 20 минут отчёта показаны
в блоке «Не помещается в план». Ни одно обязательное действие не удалено.

Пользователь видит, что сначала нужен сценарий, затем интервью, потом синтез
и рекомендации. Он может проверить готовность по артефакту, изменить оценку
и занятость. При завершении первого действия и уменьшении остатка второго
до 180 минут остаётся 405 минут работы. Факт 70 минут первого действия
сохраняется отдельно и автоматически не вычитается из другой работы.

Проверены видимый клавиатурный фокус и отключение движения через
`prefers-reduced-motion`. Выполнен визуальный просмотр снимков рабочего
пространства, плана, чата и презентации. После просмотра исправлены обрезанные
названия действий и несовпадающие поля минут на мобильной ширине; вторичный
текст сделан контрастнее. Это не полная сертификация WCAG и не проверка
скринридером. Вертикальная прокрутка на телефоне сохраняется намеренно.

Воспроизводимый браузерный сценарий:

```sh
# Отдельная offline-БД; не читает .env.
STUDYNAV_MODE=offline LLM_API_KEY= LLM_BASE_URL= LLM_MODEL= \
STUDYNAV_DB_PATH=var/evolution-qa/study.db PORT=8011 .venv/bin/python -m studynavigator
# В другом терминале, если Playwright доступен Node через NODE_PATH:
node tools/check_project_ui.cjs
```

Для проверки нужен установленный Chrome и модуль `playwright`. Скрипт принимает
только loopback URL и отказывается от live-режима. Артефакты сохраняются в
игнорируемом `var/evolution-qa/`; личный профиль браузера не используется.

## Найденные регрессии и исправления

* Начальная загрузка могла перехватить выбор только что созданного проекта.
  Создание недоступно до завершения инициализации; повторная отправка блокируется.
* Первое подтверждение действия теряло основание и диапазон оценки.
  Явно введённые поля сохраняются; изменённые оценки не получают ложное
  документальное происхождение.
* Новые поля ломали старый API плана, а старый расчёт игнорировал зависимости.
  Сохранена совместимость входа и добавлен корректный порядок в обоих путях.
* Изменение текста требования теряло ID. Существующие ID сохраняются при
  редактировании; удаление используемого требования требует исправить связи.
* Подтверждение карточки теряло прогресс. Неизменённые по смыслу действия
  сохраняют завершённость и факт. Изменённые действия сбрасываются с уведомлением;
  оценки берутся из новой карточки и требуют проверки перед пересчётом.
* Несохранённый прогресс мог исчезнуть при переходе. Добавлены защита переключения,
  предупреждение перед закрытием и явная отмена правок плана.
* Текстовым источникам ошибочно мог предлагаться seed PDF. Источники текста имеют
  отдельное представление, несуществующая страница PDF не предлагается.

## Ограничения доказательств

Структурное покрытие 4/4 означает наличие связанных, заполненных действий,
а не доказательство качества исследования. Валидатор не распознаёт любую
смысловую ошибку или любой общий текст. Нужен отдельный содержательный разбор
ответов реальной модели, когда он будет разрешён. Внешний срок проверяется
только при заданной дате начала; часовые интервалы и занятость других проектов
не моделируются. Точность оценок и практический эффект пока не проверены
на реальных пользователях.

Публичный сервер остался на предыдущей версии. Исторические live-результаты
сохранены в README отдельно от этого отчёта.
