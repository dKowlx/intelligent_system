# Материалы до 100 000 символов — 14 ноября 2026

## Изменение

Общий лимит текста проекта увеличен с 16 000 до 100 000 символов: создание
текстового проекта, PDF, дополнение текстом и смешанный комплект. Ограничения
3 PDF / 10 MiB / 100 страниц не менялись. Unicode JSON имеет отдельный предел
размера запроса с запасом для экранирования; превышение отклоняется до записи.

Hosted DeepSeek V4.1 Flash получает весь текст до 100 000 символов одним
запросом (JSON до 160 000 символов). Выбор основан на
[официальном контекстном окне модели](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models).
Для неизвестных моделей сохраняется консервативный разбор частями с дословными
цитатами, проверкой источников, пределом запросов и единым тайм-аутом.

## Найденные причины ошибки пользовательского PDF

1. Дочерний парсер корректно возвращал `text_too_large`, однако `UploadError`
   наследует `ValueError` через `CatalogError`, и широкий обработчик заменял
   точную причину на `invalid_pdf`. Исходная ошибка теперь сохраняется.
2. В задавальнике используются старые Type3-шрифты с именами глифов `/xCF`
   и без `/ToUnicode`. pypdf возвращал эти имена вместо кириллицы: 35 252 символа
   на шести страницах. Теперь для согласованных байтовых имён добавляется
   частичная Unicode-карта в памяти: извлекается 10 271 символ читаемого текста.
   PDF на диске не изменяется. Неизвестные специальные глифы не декодируются
   наугад, обычные Unicode-карты, математические шрифты и буквальный `/xHH`
   в пользовательском тексте не переписываются.
3. Первый live-разбор старого извлечения отказал с `analysis_context_limit`:
   промежуточное извлечение цитат не вместило кодированные глифы. Для текущего
   DeepSeek это сжатие исключено; модель получает исходный комплект полностью.

## Проверки

- Публичный HTTPS: подборка загружается (`201`), оригинал доступен владельцу.
- Публичный HTTPS: ровно 100 000 кириллических символов принимаются (`201`),
  добавление одного символа и отдельный текст в 100 001 символ отклоняются (`422`).
- Временные проекты граничных проверок удалены после проверки.
- Offline/mock покрывает передачу всех 100 000 символов модели без обрезания,
  восстановление ID последнего источника, один запрос DeepSeek, общий тайм-аут,
  проверки цитат для остальных моделей и сохранение прежних PDF-ограничений.
- Резервная копия перед обновлением: серверный архив
  `navigator-20261114T174206Z-15314.tar.gz`; данные и ключи при обновлении сохранены.

Платный прогон ровно на 100 000 символов не выполнялся: граница проверена через
публичное API хранения и mock провайдера. Сканированные сборники сами по себе
не получили поддержку OCR. Подготовленный PDF имеет текстовый слой.

Дополнительно обнаружено противоречие контракта неизвестных цели/результата:
промпт требовал пустой текст, запрещая единственное допускаемое схемой
происхождение пустого поля (`user`). Промпт уточнён; пустой `document` без ссылок
нормализуется только для этих двух полей. Содержательные факты без источников,
чужие ссылки и выдуманное пользовательское происхождение всё ещё отклоняются.
Регрессия проходит через HTTP-mock провайдера, настоящий MCP и валидацию карточки.
Исходный JSON неудачного live-ответа с `missing_sources` не сохранялся, поэтому
это установленное противоречие кода, а не доказанная расшифровка того ответа.
