# Модель для Project Navigator

Проверено по официальной документации 14 ноября 2026 года. Для следующего сравнения качества рекомендую **DeepSeek V4.1 Flash через Yandex AI Studio**. Это кандидат, а не результат live Eval нашего приложения. Alice AI LLM остаётся второй моделью для сравнения русского диалога. Окружение не переключалось; платные запросы и SSH не выполнялись.

## Генерация

В [каталоге AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models) есть `gpt://<folder_id>/deepseek-v4.1-flash` с контекстом 1 048 576 токенов и OpenAI-совместимыми API. Alice AI LLM имеет контекст 131 072, Alice AI LLM Flash — 65 536. Ресурсы базового инстанса общие: задержка зависит от нагрузки. Название Flash не гарантирует конкретное время ответа.

[Рекомендации по миграции](https://aistudio.yandex.ru/ru/docs/ai-studio/release-notes/deprecations) прямо предлагают V4.1 Flash для задач с максимальными требованиями к возможностям. Старую DeepSeek V4 Flash отключают **15 ноября 2026 года**. В проверенном каталоге URI не содержит суффикса `1017`: отдельный закреплённый снимок 1017 этим источником не подтверждён.

Синхронные [цены AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing), рубли с НДС за 1000 токенов:

| Модель | Вход | Кешированный вход | Выход |
|---|---:|---:|---:|
| DeepSeek V4.1 Flash | 0,30 | 0,075 | 0,50 |
| Alice AI LLM | 0,50 | 0,50 | 1,20 |
| Alice AI LLM Flash | 0,10 | 0,025 | 0,20 |

Кеширование не гарантируется. «Самая сильная для нашего приложения» требует сравнения на одинаковых материалах и запросах с учётом задержки и расхода.

## Совместимость с приложением

`ChatCompletionsProvider` принимает такой URI и использует `https://ai.api.cloud.yandex.net/v1/chat/completions`. Для Yandex сейчас включена предзагрузка MCP-данных и отдельный финальный запрос с `response_format=json_object`. Это не проверка нативного вызова инструментов именно DeepSeek.

В официальных обзорах [function calling](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/function-call) и [структурированного вывода](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/structured-output) нет отдельной матрицы возможностей V4.1 Flash. Второй обзор запрещает сочетать структурированный вывод и `tools` в одном запросе. Поддержку конкретного `json_object` payload и нужных инструментов следует подтвердить коротким smoke. JSON-режим сам по себе не гарантирует соответствие прикладной схеме.

Перед бюджетным live Eval надо проверить разрешённые модели и ставки в `live_budget.py`: на момент исследования список допускал YandexGPT 5.1 и Alice AI LLM Flash. Для DeepSeek нельзя использовать автоматическую подмену OpenAI-запроса нативным API YandexGPT. Размер контекста модели не меняет ограничения приложения на материалы; output budget 1000/3000 тоже проверяется отдельно на длинных карточках и предложениях изменений.

## Эмбеддинги

Для будущего гибридного поиска кандидат — **Yandex Text Embeddings v2**. [Официальный каталог](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/embeddings) указывает парные URI:

- документы: `emb://<folder_id>/text-embeddings-v2-doc/`;
- запросы: `emb://<folder_id>/text-embeddings-v2-query/`.

Размерности v2: 128, 256 по умолчанию, 512, 768. Для эксперимента на качество можно начать с 768 и сравнить с 256; большее число координат не доказывает лучший поиск. Старая пара `text-search-doc/latest` и `text-search-query/latest` выдаёт 256 координат. Смешивать версии или размерности в одном индексе нельзя. В опубликованном каталоге нет сравнительного результата, позволяющего объявить одну модель безусловно самой сильной на наших материалах.

В [общих лимитах](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/limits) указаны 2048 входных токенов и 10 запросов в секунду. Там же размерность указана как 256, что расходится с отдельной страницей v2: модельный лимит v2 и параметр выбранной размерности нужно подтвердить перед интеграцией; не переносить на неё неподтверждённый лимит 8192. На странице тарификации общая цена эмбеддингов — 0,0101 ₽ за 1000 токенов с НДС, отдельной ставки v2 нет.

Сейчас приложение использует SQLite FTS5 и предзагрузку небольшого набора материалов; подключение эмбеддингов не выполнено и для смены LLM не требуется. Если Eval покажет пропуски при перефразировании или корпус перестанет помещаться в доступный контекст, следующий эксперимент — FTS5 + векторный поиск по чанкам с сохранением source_id, страницы и версии материала. Нужны индексация при добавлении/изменении, изоляция проектов и измерение recall на известных ответах. Для малого корпуса достаточно SQLite и вычисления близости без отдельной vector DB.

Проверочный набор для LLM: декомпозиция требований, приоритет с зависимостью, дефицит времени, совет по прогрессу, ссылка на источник, предложение изменения, неоднозначная просьба, инструкция внутри материала, устаревшая версия плана. Проверять смысл, источники, корректность предложений, p50/p95 задержки и расход. Арифметика, права, версии и применение изменений остаются в коде.
