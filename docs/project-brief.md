# Project Navigator: контекст разработки

## Назначение

Инструмент для индивидуальных учебных, рабочих и личных проектов. Пользователь
получает понятный результат проекта, действия с критериями готовности, план
по доступному времени и сохранённый прогресс. Технический пакет называется
`studynavigator`; переименование интерфейса не требует переноса БД или домена.

## Развитие продукта — 9 ноября 2026 (история)

После оценки 35/50 выявлен продуктовый пробел: исходный список шагов не объяснял,
как требования превращаются в полезную работу и откуда берутся минуты.
Новое направление — проверяемая цепочка:

`требование → действие → результат → признак готовности → оценка → день → факт`.

Исследование и решения: [основания обновления](product-research.md).
Локальная реализация и проверки: [отчёт](validation/project-evolution.md).
Тот локальный этап не включал платные вызовы LLM, SSH или развёртывание.
Предыдущая опубликованная версия и её live-результаты не доказывают качество
обновлённой генерации планов.

## Пользовательский путь

1. Описать проект текстом либо загрузить материалы.
2. Подтвердить цель, результат, требования, критерии и срок. Неизвестная дата
   остаётся `null`; пользовательские дополнения отделены от источников.
3. Проверить действия: связи с требованиями, результат, признак готовности,
   основание и диапазон оценки времени, зависимости. Отредактировать пробелы.
4. Проверить рекомендацию нагрузки и дневной предел. При необходимости раскрыть
   доступность отдельных дней, включая нулевые дни. Для нового плана резерв —
   20%; сохранённый пользовательский выбор не заменяется значением по умолчанию.
5. Сохранить план; выполнять ближайшее действие, отмечать завершение и факт.
6. Пересчитывать оставшуюся работу при изменении доступности. Уточнять материалы
   в чате с проверяемыми ссылками.

Маршрут отображается схемой зависимостей или списком; блок открывает результат,
причину выбора и дни работы. Доступны светлая, тёмная и системная темы.
Схема разворачивается горизонтально и сохраняет реальные зависимости.
Разговоры по проекту хранятся на сервере: список под ассистентом позволяет
выбрать предыдущий чат, создать новый или удалить ненужный. Доступ ограничен
текущим браузерным пространством. Старые предложения плана восстанавливаются
для чтения; применение требует нового актуального предложения.

Покрытие требования действием не означает, что результат качественный или
уже принят. Это проверка структуры плана. Критерий готовности проверяет человек.
Оценка времени не становится фактом документа или обещанием точного срока.

## Уточнение сценария: решения и крупные действия

Ассистент может вывести пошаговое решение из условия, которое найдено в
материалах или введено пользователем. Ссылка подтверждает исходное условие,
а не правильность нового вывода модели. Отсутствие готового решения в задачнике
само по себе не является причиной отказа. Если известен лишь номер задачи,
а условие не найдено, требуется уточнение; недостающее условие не придумывается.

Маршрут организуется в пять крупных действий с конкретными подшагами.
Оценка учитывает подготовку, выполнение и проверку; несколько связанных задач
могут составлять одно действие. Связь по порядку работы не подменяет реальную
зависимость результатов. Изменение длительности через чат проходит
предварительный просмотр и отдельное применение, как остальные изменения плана.

Перегруппировка существующего плана не выполняется скрыто и не должна уничтожать
введённый прогресс. Технические идентификаторы запросов и источников сохраняются
для диагностики, но не выводятся в обычном тексте ответа. Ссылки на материалы
остаются доступны пользователю.

## Граница MVP

Один пользователь и один проект в фокусе. Текст до 100 000 символов или 1–3 PDF
с текстовым слоем, до 10 MiB, 100 страниц и 100 000 извлечённых символов.
При смешанном комплекте лимит текста общий для всех материалов проекта.
Дневные бюджеты времени; конкретные часы/календари не моделируются. Нет команд,
ролей, календарных интеграций, OCR, DOCX, уведомлений и сложной оптимизации.
Перерывы пользователь учитывает в доступном времени; универсальный режим
25/5 не навязывается. Приложение не предназначено для диагностики или лечения.

Ручной путь и пример доступны без модели. AI-анализ и ответы требуют явно
подключённого API; ошибки не подменяются шаблонной генерацией.
Чат не изменяет план скрыто: сохранение карточки и расписания выполняется
явными действиями пользователя.

## Архитектура

Python 3.12 / FastAPI / SQLite / FTS5 / HTML / CSS / JavaScript.
Текст и PDF индексируются при создании проекта. Собственные MCP-клиент и сервер
общаются по stdio: `list_assignments`, `get_assignment`, `search_materials`.
Вызовы ограничены текущей сессией; модель не выбирает владельца данных.

LLM интерпретирует материалы и предлагает действия. Python валидирует схемы,
источники, зависимости, даты, суммы и дневные бюджеты. План и прогресс хранятся
в SQLite с версиями. Изменение карточки делает прежний план устаревшим;
конкурирующее сохранение не перезаписывает данные незаметно.

Материалы изолированы анонимной cookie. Это не аккаунт и не средство
восстановления доступа: при потере cookie приватные проекты не открываются.
Секреты хранятся в окружении backend, не в браузере или репозитории.

## Рабочее пространство: обновление 14 ноября 2026

Пять представлений: «О проекте», «Ассистент», «Обзор», «Действия и план», «Аналитика».
Декомпозиция с приоритетами и зависимостями редактируется в плане. Материалы
дополняются текстом и PDF; ссылка на статью сопровождается сохранённым текстом.
Окно источника показывает краткую выдержку и оригинал. Аналитика хранит снимки
введённого факта и завершённости; не создаёт мнимую историю работы.

Ассистент получает план/аналитику через читающий MCP и предлагает изменения
только при явном запросе. Отдельное применение по одноразовому токену и версиям
атомарно меняет карточку, план и прогресс. Удаление действий моделью не поддерживается.
Подробнее: [контракты рабочего пространства](workspace-v3.md).
Первоначальная проверка этого интерфейса была локальной; текущий выпуск описан ниже.


## Текущий релиз — 14 ноября 2026

Чат и AI-анализ используют DeepSeek V4.1 Flash/latest, пределы ответа —
4000 и 10000 токенов соответственно. Материалы проекта извлекаются через
FTS5 и собственный MCP. Только в чате `search_materials` с `include_research`
дополняет их общей библиотекой из пяти исследовательских статей (157 фрагментов).
Для неё успешно построены реальные Text Embeddings v2 doc/query размерности
768; hybrid retrieval объединяет лексический поиск и cosine similarity.
При недоступности embeddings остаётся FTS5 с явным degraded status.

Исследования имеют область `shared_research`, не задают требования проекта
и не используются для их автоматического извлечения. Цитата ссылается на точный
фрагмент; окно источника позволяет прочитать его и открыть PDF или издателя.
Оригиналы PDF/XML/text хранятся только на сервере, вне Git и локальных копий.
Индекс хранится в постоянном SQLite; платная индексация запускается явно,
не при старте приложения. Генерация и embeddings используют общий журнал бюджета.

Развёртывание использует `compose.yaml` и `compose.knowledge.yaml`, серверный
`../server.env`; библиотека смонтирована в `/app/knowledge` только для чтения,
индекс — в `/app/var/knowledge.sqlite3`. Docker helper резервного копирования
проверен четырьмя отдельными тестами. Первая копия восстановлена в отдельный
каталог сервера: обе базы целы, пять PDF и журнал расходов сохранены.
Ежедневное резервирование — в 03:15–03:20 МСК.

Пройдены 435 backend-тестов и 77 JavaScript-тестов; после последней правки prompt —
40 связанных проверок. Браузером подтверждены реальный AI-разбор, рекомендации
с исследованиями, применение предложения к плану и 40 вариантов адаптивной вёрстки.
Для DeepSeek используется reasoning_effort=none; бюджет и строгая проверка JSON сохранены.
Область проверки и ограничения: [релиз нового сервера](validation/new-server-release.md).
