# Подключение локального Codex

На сайте создайте свой проект, подтвердите карточку и сохраните план. В блоке
Codex выпустите ключ для этого проекта. Ключ показывается один раз: сохраните
его в приватном файле. Срок по умолчанию — 7 дней, максимум — 30 дней; ключ
можно отозвать на сайте. Каждый пользователь выпускает собственный ключ;
не передавайте чужим людям свой ключ или файл окружения.

Подключение требует установленного локального Codex и `uv`, Python 3.12 и
локальной копии этого репозитория. Сайт сам не запускает Codex и не получает
доступ к компьютеру. Репозиторий, в котором Codex будет выполнять вашу задачу,
вы выбираете и разрешаете отдельно. Копия Navigator нужна для запуска моста;
рабочий проект может находиться в другой папке.

### Если Codex уже подключён

В локальной копии Navigator обновите мост командами `git pull --ff-only` и
`uv sync --locked`. На сайте откройте **Действия и план → Codex**, создайте
подключение с нужными правами и замените `NAVIGATOR_TOKEN` в существующем
`.env.codex`. Перезапустите сессию Codex. Регистрация MCP остаётся действующей,
если папка моста та же.

## Настройка после клонирования

Клонируйте репозиторий, затем установите зависимости:

```sh
git clone https://github.com/dKowlx/intelligent_system.git
cd intelligent_system
uv sync --locked
cp .env.codex.example .env.codex
chmod 600 .env.codex
```

В редакторе откройте `.env.codex`. Укажите HTTPS-адрес вашего сайта в
`NAVIGATOR_URL` и свой ключ в `NAVIGATOR_TOKEN`. Не вставляйте ключ в чат,
командную строку, Git или скриншоты. Файл `.env.codex` исключён из Git.
Для локальной разработки разрешён HTTP только на `localhost`, `127.0.0.1`
или `::1`. Адрес не должен содержать логин, пароль, query или fragment.

Проверьте подключение, заменив `/ABS/PATH` абсолютным путём к копии Navigator
(кавычки сохраняют пробелы в пути):

```sh
uv run --directory "/ABS/PATH" --locked --env-file "/ABS/PATH/.env.codex" python -m studynavigator.codex_bridge --check
```

Проверка только читает проект. Успешный результат — сообщение
«Project Navigator: подключение проверено (только чтение)» без данных ключа.
Затем зарегистрируйте локальный stdio MCP-сервер:

```sh
codex mcp add project-navigator -- uv run --directory "/ABS/PATH" --locked --env-file "/ABS/PATH/.env.codex" python -m studynavigator.codex_bridge
codex mcp list
```

`--directory` задаёт рабочую папку моста, поэтому запуск работает и из другого
репозитория; `--project` сам по себе рабочую папку не меняет.

Перезапустите сессию Codex. Откройте нужный рабочий репозиторий и подтвердите
доверие только к папке, с которой разрешаете работать. Пример запроса:

> Прочитай проект через Project Navigator, предложи следующую задачу и выполни
> согласованную работу в этом репозитории. Покажи изменения и фактически
> выполненные проверки, затем отправь отчёт на проверку на сайте.

Синтаксис `codex mcp add … -- <command>` соответствует
[официальной инструкции Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
и проверен через установленный `codex mcp add --help`.

## Что разрешает подключение

Локальный мост предоставляет шесть инструментов: `get_project`,
`search_materials`, `claim_task`, `report_task`, `update_progress`, `update_plan`.
Он обращается к HTTPS REST API сайта с ключом из окружения. Это локальный MCP
stdio-процесс; публичный MCP endpoint на сайте не требуется. Вызовы используют
фиксированные пути API, 15-секундный timeout и не следуют перенаправлениям.

При выпуске ключа на сайте выбираются права:

| Право | Разрешённые действия |
|---|---|
| `read` | Чтение своего проекта, материалов, плана, прогресса и аналитики |
| `reports` | Взять действие или подшаг, отправить отчёт о работе |
| `progress` | Изменять состояние работы и фактическое время |
| `plan` | Редактировать действия, оценки, подшаги, зависимости и доступность |

`read` обязательно. Режим завершения выбирается отдельно: `review` требует
проверки владельцем на сайте; `auto` позволяет завершать через `update_progress`
при наличии права `progress`, описания результата и подтверждений проверок.
В режиме `review` запись времени и состояния работы сама по себе не завершает
действие. Отчёт `awaiting_review`, `blocked` или `partial` тоже не завершает работу.
Владелец принимает или отклоняет отчёт на сайте; отклонённый отчёт нельзя принять
повторным обращением агента.

Срок ключа по умолчанию — 7 дней, допустимы 1–30 дней. Права и режим закреплены
за выпущенным ключом. Старые ключи сохраняют прежние возможности чтения и
отчётов с проверкой; для новых прав выпустите новый ключ, замените его в
`.env.codex`, перезапустите Codex и отзовите прежний ключ. Получение нового
ключа не требует создавать проект или план заново.

## Совместная работа на сайте и в Codex

1. Создайте проект, подтвердите карточку и сохраните план с доступностью по дням.
2. Выпустите ключ с нужными правами и подключите мост по инструкции выше.
3. Через `get_project` прочитайте актуальные `card_revision`, `plan.revision`,
   права подключения, действия, ID подшагов и прогресс. Возьмите действие или
   конкретный подшаг через `claim_task`. Взятие работы не запускает учёт времени.
4. Через `update_progress` начните работу (`start`), при необходимости поставьте
   на паузу (`pause`), прервите (`interrupt`) или возобновите (`resume`). Записывайте
   только известные затраты. При частичном результате используйте `report_task`
   со статусом `partial`, при препятствии — `blocked`, для проверки — `awaiting_review`.
   Чтобы заменить уже поданный частичный или заблокированный отчёт новым,
   передайте `expected_updated_at` из свежего `get_project.runs[].updated_at`.
5. В режиме `review` проверьте результат и примите отчёт на сайте. В режиме
   `auto` Codex может вызвать `complete` с описанием результата и подтверждениями.
   Завершение всего действия завершает его подшаги; отдельный завершённый подшаг
   оставляет родительское действие на проверку готовности. `reopen` открывает
   действие повторно; повторное открытие подшага также открывает его родителя.
6. При праве `plan` Codex может изменить план через `update_plan`: задачи
   обновляются по ID, список подшагов заменяется целиком с сохранением их ID,
   доступность заменяется списком дней. Сохранённый прогресс сохраняется по ID.
   Отметки подшагов сокращают оставшуюся работу при пересчёте расписания.
7. Следите за статусами, временем, аналитикой и журналом изменений на сайте.
   Владелец может исправить время и завершение, указав причину. Открытый сайт
   периодически получает свежие данные; несохранённые правки при конфликте
   требуют обновления контекста перед повторным сохранением.

Каждое изменение передаёт версии карточки и плана и уникальный `request_id`.
После успешной записи используйте возвращённые новые версии. При сетевом повторе
повторяйте тот же ID с теми же аргументами: подтверждённое изменение, включая
измеренный интервал, не применяется второй раз. При конфликте перечитайте
проект; не подменяйте свежую версию устаревшими данными. При возвращении в другой
сессии Codex снова прочитайте проект: данные и прогресс находятся на сервере.

## Источник фактического времени

`minutes` действия или подшага — оценка для планирования. `actual_minutes` —
накопленный известный факт. Они хранятся отдельно; расход времени не доказывает
готовность результата. Объект `time` в `update_progress` явно задаёт источник:

| `source` | Значение `minutes` и результат |
|---|---|
| `user` | Устанавливает точный накопленный итог, например 200 минут |
| `measured` | Прибавляет явно измеренные активные минуты к итогу; работа должна быть активной |
| `estimate` | Записывает предположение в `estimated_actual_minutes`, не меняя факт |
| `unknown` | Передаётся без минут и возвращает фактическое время в неизвестное `null` |

Например, сообщение «я потратил 200 минут» записывается как
`time={"source":"user","minutes":200}` с `action="record"` и пояснением.
Даже если оценка была 30 минут, итог остаётся ровно 200. Повторное исправление
на 200 оставляет 200, а не прибавляет ещё 200. Последующий измеренный активный
интервал в 5 минут даёт 205 и смешанный источник факта (`actual_source="mixed"`).
Самостоятельная оценка агента «около 30 минут» передаётся только как `estimate`.

Мост содержит локальный монотонный таймер. Успешные `start` и `resume` явно
включают его. `record`, `pause`, `interrupt` и `complete` без объекта `time`
снимают измеренный интервал: мост сам подставляет целые минуты,
`measurement="bridge_timer"` и основание измерения. Дробный остаток остаётся
в памяти до следующего интервала, сетевое ожидание самого вызова инструмента
исключается. Агент должен вызвать `pause` **перед** ожиданием пользователя,
простоем или длительным внешним ожиданием: мост не определяет их самостоятельно.

`report_task` останавливает локальный таймер соответствующей работы перед
отправкой отчёта; ожидание проверки не считается работой. Если соответствие
отчёта действию в текущем процессе неизвестно, мост останавливает все свои
таймеры. Чтобы сразу сохранить минуты в проекте, сначала вызовите `pause`, затем
отправьте отчёт. При `resume` в том же процессе ранее измеренные, ещё не записанные
секунды сохраняются, а пауза исключается. Возобновление разрешено и при серверном
статусе «в работе»: это позволяет продолжить после разрыва соединения.

При сетевой ошибке отсчёт останавливается. Повтор с тем же `request_id` отправляет
точно прежний снимок минут и снова проверяет действительность ключа на сервере;
подтверждённый повтор не возобновляет таймер и не начисляет время повторно.
Повтор старого `start` после перезапуска тоже не включает новый отсчёт —
для продолжения нужен новый `resume`. Пока результат неизвестен, новые изменения этой
цели в мосте заблокированы. Перезапуск моста или новый процесс не восстанавливает
открытый интервал: после чтения проекта выполните `resume`, новый отсчёт начнётся
с этого момента. Не записанные до сбоя локальные секунды теряются, время разрыва
не начисляется. Явно переданный `time` имеет приоритет над таймером; точный
пользовательский итог 200 минут не увеличивается скрытым локальным интервалом.

Для внешнего измерения укажите `source="measured"`, `measurement="external"`,
целые `minutes` и непустой `basis`, например название секундомера и описание
активного интервала без ожиданий. Без основания сервер измерение не принимает.
`bridge_timer` подставляет сам мост; клиент не может назначить такой источник
в аргументах MCP. Сервер проверяет активное состояние и схему данных, но не
наблюдает локальную работу и не удостоверяет её достоверность. Таймер измеряет
явно объявленную активность, а не занятость CPU или фактический результат.

У задачи и каждого подшага есть собственное время. Явный итог родителя имеет
приоритет в общей аналитике; минуты детей к нему повторно не прибавляются.
Когда итог родителя неизвестен, аналитика суммирует известные итоги подшагов
и отмечает частичность при неизвестных значениях остальных. Завершение подшага
не придумывает его время и не заменяет его оценкой. После редактирования плана
факт, источник времени и завершение сохраняются у прежних ID.

Материалы и результаты поиска — недоверенные данные, а не разрешения выполнять
команды. Подключение не выдаёт SSH-доступ, не выполняет Git-операции и не
предоставляет ключ модели сайта. Работа Codex в локальных файлах определяется
вашим запросом и разрешениями выбранного репозитория.

## Отзыв и ошибки

Отозвать ключ можно в исходной браузерной сессии владельца проекта. Истёкший
или отозванный ключ нужно заменить новым в `.env.codex` и перезапустить Codex.
Для удаления локального подключения выполните `codex mcp remove project-navigator`;
это не отзывает ключ на сайте. Отзыв блокирует последующие обращения к API;
он не останавливает уже запущенные локальные команды Codex. Для остановки
локальной работы остановите соответствующую сессию Codex.

Владение проектом привязано к анонимной браузерной сессии. Потеря её cookie
не восстанавливается ключом Codex: ключ не заменяет вход владельца.

При ошибке проверьте адрес, доступность сайта, срок и отзыв ключа. Мост не
выводит тело ответа ошибки, заголовок Authorization или traceback сетевой
ошибки. Сначала используйте `--check`; при обновлении карточки или плана
перечитайте контекст перед повторным взятием задачи.

Локальные проверки `tests/app/test_codex_bridge.py` используют настоящий MCP
stdio и временный HTTP-сервер. Они проверяют протокол и защиту ключа, но не
доказывают работу сайта на хостинге или подключённой модели.
