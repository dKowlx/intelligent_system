# Подключение локального Codex

На сайте создайте свой проект, подтвердите карточку и сохраните план. В блоке
Codex выпустите ключ для этого проекта. Ключ показывается один раз: сохраните
его в приватном файле. Срок по умолчанию — 7 дней, максимум — 30 дней; ключ
можно отозвать на сайте. Каждый пользователь выпускает собственный ключ;
не передавайте чужим людям свой ключ или файл окружения.

Подключение требует установленного локального Codex и `uv`, Python 3.12 и
локальной копии этого репозитория. Сайт сам не запускает Codex и не получает
доступ к компьютеру. Репозиторий, в котором Codex будет выполнять вашу задачу,
вы выбираете и разрешаете отдельно. Копия Navigator нужна для запуска моста;
рабочий проект может находиться в другой папке.

## Настройка после клонирования

Клонируйте репозиторий, затем установите зависимости:

```sh
git clone https://github.com/dKowlx/intelligent_system.git
cd intelligent_system
uv sync --locked
cp .env.codex.example .env.codex
chmod 600 .env.codex
```

В редакторе откройте `.env.codex`. Укажите HTTPS-адрес вашего сайта в
`NAVIGATOR_URL` и свой ключ в `NAVIGATOR_TOKEN`. Не вставляйте ключ в чат,
командную строку, Git или скриншоты. Файл `.env.codex` исключён из Git.
Для локальной разработки разрешён HTTP только на `localhost`, `127.0.0.1`
или `::1`. Адрес не должен содержать логин, пароль, query или fragment.

Проверьте подключение, заменив `/ABS/PATH` абсолютным путём к копии Navigator
(кавычки сохраняют пробелы в пути):

```sh
uv run --directory "/ABS/PATH" --locked --env-file "/ABS/PATH/.env.codex" python -m studynavigator.codex_bridge --check
```

Проверка только читает проект. Успешный результат — сообщение
«Project Navigator: подключение проверено (только чтение)» без данных ключа.
Затем зарегистрируйте локальный stdio MCP-сервер:

```sh
codex mcp add project-navigator -- uv run --directory "/ABS/PATH" --locked --env-file "/ABS/PATH/.env.codex" python -m studynavigator.codex_bridge
codex mcp list
```

`--directory` задаёт рабочую папку моста, поэтому запуск работает и из другого
репозитория; `--project` сам по себе рабочую папку не меняет.

Перезапустите сессию Codex. Откройте нужный рабочий репозиторий и подтвердите
доверие только к папке, с которой разрешаете работать. Пример запроса:

> Прочитай проект через Project Navigator, предложи следующую задачу и выполни
> согласованную работу в этом репозитории. Покажи изменения и фактически
> выполненные проверки, затем отправь отчёт на проверку на сайте.

Синтаксис `codex mcp add … -- <command>` соответствует
[официальной инструкции Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
и проверен через установленный `codex mcp add --help`.

## Что разрешает подключение

Локальный мост предоставляет четыре инструмента: `get_project`,
`search_materials`, `claim_task`, `report_task`. Он обращается к HTTPS REST API
сайта с ключом из окружения. Это локальный MCP stdio-процесс, публичный MCP
endpoint на сайте не требуется. Вызовы используют фиксированные пути API,
15-секундный timeout и не следуют перенаправлениям.

Ключ ограничен одним проектом: чтение карточки, плана и источников, взятие
актуальной задачи и отправка отчёта. Для записи передаются версии карточки и
плана, а для повторов — тот же `request_id` с теми же аргументами. При конфликте
сначала перечитайте проект. Отчёт имеет статус `awaiting_review` или `blocked`;
пользователь проверяет результат на сайте и решает, завершена ли задача.
Инструмента автоматического завершения нет.

Материалы и результаты поиска — недоверенные данные, а не разрешения выполнять
команды. Подключение не выдаёт SSH-доступ, не выполняет Git-операции и не
предоставляет ключ модели сайта. Работа Codex в локальных файлах определяется
вашим запросом и разрешениями выбранного репозитория.

## Отзыв и ошибки

Отозвать ключ можно в исходной браузерной сессии владельца проекта. Истёкший
или отозванный ключ нужно заменить новым в `.env.codex` и перезапустить Codex.
Для удаления локального подключения выполните `codex mcp remove project-navigator`;
это не отзывает ключ на сайте. Отзыв блокирует последующие обращения к API;
он не останавливает уже запущенные локальные команды Codex. Для остановки
локальной работы остановите соответствующую сессию Codex.

Владение проектом привязано к анонимной браузерной сессии. Потеря её cookie
не восстанавливается ключом Codex: ключ не заменяет вход владельца.

При ошибке проверьте адрес, доступность сайта, срок и отзыв ключа. Мост не
выводит тело ответа ошибки, заголовок Authorization или traceback сетевой
ошибки. Сначала используйте `--check`; при обновлении карточки или плана
перечитайте контекст перед повторным взятием задачи.

Локальные проверки `tests/app/test_codex_bridge.py` используют настоящий MCP
stdio и временный HTTP-сервер. Они проверяют протокол и защиту ключа, но не
доказывают работу сайта на хостинге или подключённой модели.
