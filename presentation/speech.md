# Project Navigator — текст выступления

Project Navigator — веб-инструмент для учебных, рабочих и личных проектов. Он превращает описание задачи и материалы в требования, последовательность действий и сохраняемый план. Пользователь получает ответ на три вопроса: что должно получиться, с чего начать и по какому результату считать действие выполненным.

Пользователь загружает PDF или добавляет текст. Приложение извлекает материалы, а модель формирует карточку проекта: цель, итоговый результат, требования и критерии. После подтверждения карточки открываются действия, расписание, ассистент и аналитика. У действий есть подшаги, зависимости, приоритет и условие завершения. Пользователь задаёт доступность и отмечает прогресс; план сохраняется между посещениями.

Для проверки я создал новый проект на опубликованном сайте и загрузил «Личный проект.pdf». До запуска отдельно выписал ожидаемые требования: сформулировать задачу и MVP, реализовать MCP и подключённую LLM, создать интерфейс, разместить сервис, провести Eval, оформить README и публичный репозиторий, подготовить HTML-презентацию и передать ссылки в LMS.

Приложение выделило семь требований, пять критериев и пять связанных действий с семнадцатью подшагами:

1. Определить задачу, пользователя, сценарий и границы MVP; согласовать формулировку.
2. Реализовать MCP-интеграцию и AI-логику с LLM.
3. Создать интерфейс и развернуть сервис на хостинге.
4. Провести Eval, разобрать ошибки, оформить README и публичный репозиторий.
5. Подготовить интерактивную HTML-презентацию, демонстрацию и ссылки для LMS.

Основные обязательные результаты из независимого списка присутствуют в карточке и действиях приложения. Названия сгруппированы, поэтому число требований не обязано совпадать с числом шагов. Например, архитектура и источники входят в общий шаг оформления README. Календарный срок документом не задан — приложение оставило его пустым.

Польза плана видна на конкретных результатах. Шаг про MCP заканчивается работающими вызовами инструментов и схемой интеграции. Шаг про хостинг — доступным сервисом и выполнением основного сценария. Шаг про Eval — сохранёнными результатами и разбором ошибок. Студент сверяет готовность с этими результатами, затем отмечает действие выполненным и переходит к следующему. Зависимости связывают формулировку задачи, реализацию, проверку и оформление.

Полученную карточку я подтвердил без изменения ответа модели. Затем приложение рассчитало расписание по заданной доступности и сохранило план на сервере. Проверка охватила загрузку исходного документа, настоящий AI-разбор, подтверждение карточки и сохранение расписания.

Технически система состоит из веб-интерфейса, FastAPI, SQLite, языковой модели и собственного MCP-клиента и сервера. MCP предоставляет материалы и инструменты проекта. Ассистент использует источники и текущий прогресс, отвечает на вопросы и предлагает изменения действий. Изменения применяются после подтверждения пользователя. Это связывает обсуждение задачи с её требованиями, планом и фактическим выполнением.
