# Project Navigator: выпуск

Выполняй только запрошенный объём публикации и проверки.

## Контекст

- Прочитай корневой [AGENTS.md](../../../AGENTS.md) и [описание проекта](../../../docs/project-brief.md).
- Для структуры документации используй [submission.md](references/submission.md).
- Сохраняй существующие команды запуска и окружение.

## Порядок работы

1. Проверь код, команды, конфигурацию и текущие ссылки.
2. При проверке воспроизводимости выполни запуск по README в отдельной среде с lock-файлом. Не удаляй рабочие данные.
3. Проверь затронутый сценарий: интерфейс, LLM, MCP-клиент, MCP-сервер и ответ по источникам.
4. При развёртывании проверь переменные окружения, постоянное хранение данных, публичный адрес и основной сценарий.
5. Обнови README по фактически реализованным возможностям и выполненным проверкам.
6. Сообщи изменённые файлы, результат проверок и ссылку на сервис.

## Проверяемость

- Различай offline/mock, реальный MCP-обмен и вызов подключённой модели.
- Доступный `/health` не подтверждает работу всего пользовательского сценария.
- Указывай только фактически полученные результаты. Невыполненную проверку не называй успешной.
- Ключи остаются в окружении сервера. Не включай их в код, репозиторий, документацию и логи.
